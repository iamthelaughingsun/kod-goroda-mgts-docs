# ИИ-слой: провайдер, контракт, ограничения

Проверено 13.11.2026 на живых запросах, код — `ai/extract.py`.

## Решение для шоукейса

Своих ключей и своего железа нет — хакатон. Поэтому:

- **демо и разработка**: `qwen3.8-flash` через гейтвей `opencode.ai/zen/go/v1`
  (уже настроен на машине, отдельный ключ OpenRouter не нужен);
- **переезд на OpenRouter**: меняется `LLM_BASE_URL` и `LLM_KEY_ENV`, код тот же;
- **прод у заказчика**: GigaChat или YandexGPT со structured output через тот же
  OpenAI-совместимый фасад — три переменные окружения, ни строчки кода.

Последний пункт — это не «мы потом перепишем», а свойство контракта: код не знает,
кто за фасадом. На защите это отвечает на вопрос 152-ФЗ без отговорок.

## Что проверено фактически

| Модель | `response_format: json_schema` | Результат |
|---|---|---|
| `qwen3.8-flash` | принят | валидный JSON по схеме, по-русски |
| `qwen3.8-max` | принят | валидный JSON по схеме, по-русски |

Два подводных камня, на которых легко потерять час:

1. **Нужен браузерный `User-Agent`** — без него Cloudflare отдаёт `403,
   error code: 1010` ещё до нашей авторизации.
2. **Нужен заголовок `x-opencode-session`** — без него шлюз отвечает
   `MissingSessionID` и просит сессию.

Оба уже проставлены в `ai/extract.py`; при переезде на другого провайдера они
становятся пустыми через `LLM_EXTRA_HEADERS`.

Третья особенность: qwen кладёт рассуждения в отдельное поле
`reasoning_content`, а не в `content`. Если парсить неаккуратно, покажется, что
модель «думает вслух» в ответе. Мы читаем только `content`.

## Контракт вывода

```json
{
  "has_problem": true,
  "topic": "наставничество",
  "problem": "Наставник отвечает раз в неделю, при росте задач это блокирует работу.",
  "severity": 3,
  "quote": "наставник отвечает раз в неделю",
  "confidence": 0.85
}
```

Правила, без которых слой бесполезен:

- **`has_problem: false` — валидный ответ.** «Ок», «всё хорошо», «нормально»
  дают пустые `topic`/`problem`/`quote`, `severity: 1`, `confidence < 0.3`.
  Это проверено на пяти отзывах: два нейтральных и два позитивных не дают
  ни одной ложной тревоги. Ложная тревога хуже пропуска — наставник перестаёт
  верить системе после второй.
- **`quote` — дословный фрагмент.** Не пересказ. В интерфейсе это единственное,
  что связывает вывод ИИ с реальностью.
- **Температура 0.** Один и тот же отзыв должен давать один и тот же вывод,
  иначе демо не воспроизводится, а тесты бессмысленны.
- **Валидация и один retry.** JSON без схемы — не результат. Проверка ручная,
  без pydantic: лишняя зависимость в хакатоне.
- **Язык — в промпте.** Без строки «отвечай по-русски» qwen выдал английские
  `topic`/`problem` при русском отзыве. Проверено, исправлено.

## Что делать перед демо

- **Кэш по хэшу текста**: один отзыв не должен стоить дважды. 300–500
  синтетических отзывов прогонять заранее, а не на сцене.
- **Батчи по 20–50 отзывов** на запрос — дешевле и быстрее, чем по одному.
- **Считать токены** по полю `usage` и показывать их в прогоне: вопрос «сколько
  это стоит в месяц» на защите будет задан.
- **Не обещать тональность** как метрику: «негативный» ≠ «проблема». Мы
  извлекаем проблему, а не настроение.
