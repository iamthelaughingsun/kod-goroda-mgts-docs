# Роадмап

Владельцы: **B** — бэкенд, **F** — фронтенд, **FS** — фуллстек.

Правило: фаза считается закрытой, когда выполнен её критерий готовности и она
видна в демо. Фазы идут параллельно там, где это возможно, — людей трое.

## Жёсткие вводные (из брифинга 13.11, `docs/briefing-notes.md`)

- **Квалификация — до 19 ноября.** Финалистов объявляют 23-го, финал — 26-го.
- **На финале 3 часа на разработку.** Мы приходим с заготовкой и за три часа
  подключаем их Excel. Всё, что не влезает в три часа, отрезаем заранее.
- **Данные — файлы Excel и Word**, анонимизированные ID. API нет.
- **Вопросы одинаковые каждый месяц**, набор фиксирован — динамика считается честно.
- **Один интерфейс**, два не нужны. Фирменный стиль не обязателен.
- Критерии: методическая обоснованность, соответствие задаче и полнота,
  реализуемость и измеримость, качество защиты. Питч — отдельный критерий с весом.

Следствие для плана: цель не «демо через неделю», а «заготовка, которая за три часа
принимает чужие файлы». Адаптивный опрос из скоупа финала уходит — данных для него
нет, писать в чужую форму некуда; остаётся слайдом как развитие.

## Ф1 · Данные и каркас (день 1, B + FS)

- Каноническая схема: `intern`, `mentor`, `group`, `period`, `survey`,
  `response`, `response_item` (оценка + комментарий).
- Генератор синтетики: 40 стажёров × 6 месяцев, с заложенными сценариями —
  ровный рост, провал на 3-м месяце, смена наставника, молчащий стажёр,
  наставник, ставящий всем одинаково.
- Загрузчик CSV + адаптер под API сервиса анкетирования (интерфейс, реализация
  позже).
- Критерий: `make seed` заполняет базу, в дашборде видны 40 стажёров.

## Ф2 · Метрики и нормализация (день 2, B)

- Средние по месяцам, тренд, отклонение стажёра от своей группы.
- Нормализация строгости наставника: z-оценки внутри наставника, а не по всей
  программе.
- Риск на правилах: падение оценки, два пропущенных опроса, серия негативных
  комментариев.
- Критерий: на синтетике находятся заложенные сценарии, ложных срабатываний
  не больше одного на 40 стажёров.

## Ф3 · ИИ-слой (день 3, FS)

- Из комментария: тема, суть проблемы, острота, цитата, уверенность.
- Кластеризация тем по программе и по наставнику.
- Сводка по стажёру за 6 месяцев.
- Жёсткое правило: нет сигнала — ответ «не найдено», а не догадка.
- Критерий: на 50 комментариях размеченных вручную точность извлечения проблем
  не ниже 80%, все выводы с цитатами.

## Ф4 · Дашборд (день 4, F)

- Экран программы: динамика, распределение, топ проблем, лента рисков.
- Карточка стажёра: таймлайн 6 месяцев, комментарии с подсветкой проблем.
- Карточка наставника: как его группа проходит программу.
- Фильтры: месяц, группа, наставник.
- Критерий: с экрана программы за два клика попадаем в стажёра из группы риска.

## Ф5 · Приём их файлов за три часа (день 5, B + FS)

Это то, что определяет финал: их Excel с незнакомыми названиями колонок должен
разбираться без правки кода, а не «мы подгоним под наш формат».

- Парсер Excel и Word: два листа (стажёры, наставники), поиск колонок по словарю
  синонимов, отчёт «что распознано, что нет».
- Импорт одним шагом: загрузил файл → предпросмотр распознанного → подтвердил.
- Репетиция на чужом файле: просим кого-то вне команды собрать таблицу «как получится»
  и разбираем её без правок.
- Критерий: файл с произвольными заголовками разбирается за один проход, непонятые
  колонки перечислены списком, а не проглочены молча.

## Ф6 · Питч и упаковка (день 6, все)

- Питч как отдельный артефакт, потому что качество защиты — критерий с весом:
  проблема, что делает система, три находки на их данных, ограничения, что дальше.
- `docker compose up` на одной машине, README с запуском, демо-датасет в репозитории.
- Прогон вопросов жюри через движок спора (`team-debate-engine`).
- Критерий: с чистого клона проект поднимается одной командой; питч укладывается
  в регламент и отвечает на вопрос «почему это измеримо».

## Что режем первым, если времени меньше

1. Ф4 — оставить один экран программы и карточку стажёра, без карточки наставника.
2. Ф3 — один вызов LLM на комментарий без кластеризации тем.
3. Ф2 — три метрики вместо десяти.

Ядро — парсер их файлов (Ф5), анализ комментариев (Ф3) и экран программы (Ф4).
Без парсера нет демо на финале, без двух других нет смысла в парсере.

## Риски

| Риск | Что делаем |
|---|---|
| Нет доступа к сервису анкетирования | синтетика по структуре опросов + адаптер за интерфейсом, коннектор последним |
| ИИ «находит» несуществующие проблемы | цитата + порог уверенности + «не найдено» как валидный ответ |
| Малая выборка, шум | нормализация по наставнику, отказ от сравнения абсолютных средних |
| Три человека на шесть фаз | параллельные треки: B — данные и метрики, F — интерфейс, FS — ИИ и интеграции |
